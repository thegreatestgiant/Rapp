# Tzitzis Source Sheet Audit

## Summary
Audited the `tzitzis.md` master source sheet (`000 Source PDFs/tzitzis.pdf`, Subject: *Halacha*, Fall 2026 Midterm). Resolved systematic parsing errors where 14 body paragraphs containing legal terms (`טלית`, `מלבושים`, `פטור`, `מדאורייתא`) triggered false source detection, inflating the total count from 52 to 66. Re-attributed responsa sources (`שו"ת יחווה דעת`, `שו"ת מנחת יצחק`, `שו"ת מנחת שלמה`, `שו"ת הר צבי`) to their canonical authors, cleaned up 13 junk author notes and 14 phantom source notes, and accurately captured multi-page continuation crops.

---

## Root Causes Identified & Parser Fixes (`999 Scripts/process_source_sheets.py`)

1. **False Header Triggers on Keyword Matches in Numbered Documents**:
   - **Root Cause**: `extract_sources_and_images()` previously used `KNOWN_HEADER_KEYWORDS` as an alternative to number prefixes for any block with `y0 > 30` and length < 150 chars. In documents with numbered sources (like `tzitzis.pdf` having `(1` through `(52`), legal discussions discussing `טלית`, `מלבושים`, or citing `תוספות` inside the body triggered 14 false header detections.
   - **Fix**: Added document-wide detection for numbered headers (`has_numbered_doc`). When a document is structured with numbered sources, the parser strictly requires a numbered prefix (`has_num_prefix` or `has_special_num`), suppressing false keyword triggers while preserving keyword detection on non-numbered sheets.

2. **Responsa Book-to-Author Direct Mapping**:
   - **Root Cause**: Citations like `שו"ת יחווה דעת`, `שו"ת מנחת יצחק`, `שו"ת מנחת שלמה`, and `שו"ת הר צבי` previously either fell back to token extraction (`שו"ת יחווה`, creating junk author `שו''ת יחווה.md`) or collided with broader mappings (e.g., broad `'מנחת'` mapping to `רבי אשר וייס`).
   - **Fix**:
     - Introduced `RESPONSA_SPECIAL_MAP` in `parse_citation()` mapping:
       - `יחווה דעת` -> Author: `[[רב עובדיה יוסף]]`, Book: `שו"ת יחווה דעת`
       - `מנחת יצחק` -> Author: `[[רבי יצחק יעקב וייס]]`, Book: `שו"ת מנחת יצחק`
       - `מנחת שלמה` -> Author: `[[רבי שלמה זלמן אויערבאך]]`, Book: `שו"ת מנחת שלמה`
       - `הר צבי` -> Author: `[[רב צבי פסח פרנק]]`, Book: `הר צבי`
     - Removed overly broad `'מנחת'` key from `AUTHOR_CANONICAL_MAP` to avoid misattributing *Minchas Yitzchak* and *Minchas Shlomo* to Rav Asher Weiss.

3. **Running Header Distinguishing for Continuation Crops**:
   - **Root Cause**: Top-of-page continuation detection previously grabbed running headers (e.g. standalone single-line `הלכות ציצית` on pages 3 and 5) or missed real multi-page continuations.
   - **Fix**: Filtered out single-line short running headers (`<= 20` chars and single line) when checking top content blocks, ensuring continuations only capture actual continuation text (e.g. Source 9 on p2, Source 18 on p3, and Source 43 on p6).

4. **Existing Source Reuse Return Signature Bug**:
   - **Root Cause**: In `process_source()`, when reusing an existing source with the same image and heading, the function returned a 2-tuple `(existing_stem, heading_to_use)` instead of a 3-tuple `(existing_stem, heading_to_use, False)`, causing a `ValueError: not enough values to unpack (expected 3, got 2)`.
   - **Fix**: Fixed the return statement to consistently return a 3-tuple.

## Duplicate `(2)` Resolution & Note Preservation Safeguards

### 1. Root Cause of `(2)` Headings
When the parser re-ran after fixing the 14 phantom sources, the crop numbers shifted on pages 3, 5, and 6. Because the source notes already existed with old crop names, `process_source()` thought they were distinct citations from the same Siman and appended duplicate `### ... (2)` headings and links to 8 sources (Sources 23, 24, 26, 39, 42, 47, 49, 50).

### 2. Root Cause of Note Overwriting on 2-Part Filenames
In `match_existing_source()`, filenames with only two parts (e.g. `משנה ברורה - משנה ברורה סימן ח ס''ק ב.md` where author equals book name) failed the `len(parts) >= 3` check and fell back to `write_text()`, overwriting notes.

### 3. Parser Fixes in `999 Scripts/process_source_sheets.py`
- Added direct file path matching in `match_existing_source()` and added support for 2-part filenames (`len(parts) == 2`).
- Tracked per-run sheet usage (`seen_in_sheet`) in `process_source()` to ensure re-runs of the same sheet update image crops cleanly and reuse existing headings without ever appending spurious `(2)` suffixes.
- Completely removed all `(2)` headings and cleaned up links across `tzitzis.md` and all affected source files.
